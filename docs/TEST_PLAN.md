# Runnel v0.1 Test Plan

Generated by `/plan-eng-review` on 2026-08-20.
Planning branch: `feat/v0.1`; released from tag `v0.1.0` and maintained on `main`.
Repo: `github.com/ArshyaAI/runnel` (public release: https://github.com/ArshyaAI/runnel/releases/tag/v0.1.0)

## Affected commands

- `runnel` / `runnel scan` — fast read-only workflow radar and partial-permission output.
- `runnel scan --json` — strict snapshot schema without ANSI or private action data.
- `runnel explain <finding>` — deep evidence, contradictions, and unsupported states.
- `runnel recover` — exact-candidate selection, token confirmation, identity-bound
  SIGTERM, and verified/refused/partial/failed receipt states.
- `runnel history` / `runnel receipt` — private receipt index and exact local receipt.
- `runnel receipt <id> --share` — separately encoded allowlisted share receipt.
- `runnel doctor` / `--self-test` — local capability and privacy-safe in-memory checks.

## Key interactions to verify

- Empty, single-workflow, many-workflow, rootless-cycle, and mixed unrelated process trees.
- Protected current Runnel/TTY/cmux/editor/database/sync/security identities remain visible
  and never enter a selectable set.
- Active, intentionally paused, unsupported, contradictory, and unavailable fixtures
  remain structurally unselectable.
- Exact supported childless stale fixture requires the displayed token and produces a
  durable prepared receipt before any signal.
- Wrong pidversion returns `ESRCH` and leaves the owned test child alive; the exact token
  sends only SIGTERM to that child.
- A test child that `exec`s a distinct helper invalidates the old token; the replacement
  survives the old token and only its new exact token can deliver SIGTERM.
- Action-time WAL/schema/rollout/file/descriptor/origin changes refuse with zero signals.
- Verified outcomes reconcile target absence, protected presence, signal count, and
  selected-process RSS observations exactly.

## Edge cases

- PID exit/reuse, process exec, new child, parent disappearance, PPID cycles, and zombies.
- Permission denied, missing private libproc symbol, missing/slow/malformed `lsof` or
  `sample`, output ceiling, context cancellation, and escaped probe descendant.
- Unsigned, altered, re-signed, wrong-team, wrong-identifier, wrong-digest, and mismatched
  ChatGPT/Codex/Node/worker chains.
- Busy/changing SQLite WAL, incompatible columns/values, truncated/unknown rollout tail,
  changed inode, and changing size/mtime.
- Disk full, permission error, crash after prepared receipt, fsync/rename failure, and
  recovery of the last durable transaction state.
- Symlinked/wrong-owner receipt directories and temp/final targets, exclusive-create ID
  collisions, no-follow enforcement, duplicate finalization refusal, immutable
  `prepared.json`/`result.json`, and final inode/mode verification.
- Terminal resize, Ctrl-C before/after action boundary, panic/error restoration,
  non-TTY recovery refusal, and JSON output with no ANSI.
- Share snapshot and share receipt reject all forbidden identifiers, paths, argv, raw
  errors, stack text, ports, and unknown fields.

## Critical paths

1. Read-only scan completes under the latency/RSS budgets and leaves no child or goroutine.
2. Active and paused cases are understandable and cannot construct a recovery plan.
3. Deliberate stale lab case writes prepared receipt, revalidates, identity-signals its
   one owned child, verifies target absence/protected presence, and finalizes receipt.
4. Any changed identity/evidence refuses before the kernel signal call.
5. Release archives install on native Darwin arm64/amd64 and pass `doctor --self-test`.
